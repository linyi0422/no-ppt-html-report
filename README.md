# 不用 PPT 的 HTML 汇报页

这个仓库用来沉淀一种新的汇报展示方式：不用 PPT，也不用反复生成静态图片，而是把复盘、方案、问题说明做成可以在浏览器里调节的 HTML 页面。

我暂时把这种形式叫做：**可调式 HTML 汇报页**。

它的核心不是“网页设计”，而是把一页汇报材料做成可调节、可截图、可发布、可复用的展示稿。

## 适合什么场景

- 复盘汇报
- 问题说明
- 方案对齐
- 咨询前置材料
- 一页纸总结
- 需要现场调整信息重心的表达材料

## 为什么不用 PPT

PPT 适合正式演示，但在快速沟通里经常有几个问题：

- 改字号、留白、层级很慢
- 截图传播不够灵活
- 一旦想突出某个模块，往往要重新排版
- 多次迭代容易变成“调格式”而不是“调表达”

HTML 的好处是，页面本身可以带控制面板。内容、布局和截图状态可以在浏览器里直接调。

## 这种形式的基本能力

- 模块级布局调节
- 正文字号和行距调节
- 重点区域权重调节
- 关键问题字号调节
- 纯净截图模式
- 可通过 GitHub Pages 公开访问

## 怎么跟 AI 沟通

如果你想把一段内容做成这种形式，不要只说“帮我做成 HTML”。更好的说法是：把材料、受众、重点、可调项和截图场景一起告诉 AI。

可以直接这样说：

```text
我想把下面这段材料做成一个“可调式 HTML 汇报页”，不要做 PPT。

使用场景：
我要把它发给【目标对象】，希望对方快速理解【核心问题/核心结论】。

内容材料：
【粘贴原文、复盘、方案、会议记录或问题说明】

请你帮我做成一个单页 HTML，要求：
1. 页面本身就是可展示的汇报稿，不要做成普通文章。
2. 信息结构分成 3-5 个模块，每个模块有清楚标题。
3. 最重要的问题/结论要做成视觉中心。
4. 右侧或顶部加入调节面板，可以调字号、行距、模块间距、重点区域大小、关键问题字号。
5. 加一个“纯净模式”，隐藏控制面板，方便截图或公开展示。
6. 所有 CSS 和 JS 写在一个 HTML 文件里，方便直接打开和部署到 GitHub Pages。
7. 视觉风格要符合这个场景：【专业/克制/自然/科技/咨询/学术/产品汇报等】。

请先整理信息结构，再直接输出完整 HTML 文件。
```

也可以更短地说：

```text
把这段内容做成可调式 HTML 汇报页：不是 PPT，不是静态海报，而是一个带控制面板的单页展示稿。需要能调模块布局、字号、留白、重点区域和截图模式。
```
